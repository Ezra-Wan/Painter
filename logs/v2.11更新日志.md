# Painter v2.11.0 更新日志

**发布日期**: 2026-05-07  
**Minecraft 版本**: 1.21  
**NeoForge 版本**: 21.0.167+  
**前置依赖**: Laplace API 0.7.1

---

## 🎯 版本概览

v2.11.x 是一个专注于**多人游戏同步修复**和**架构解耦合**的重要更新。本次更新主要完成了以下工作：

1. **架构重构**: 完全移除 PaintChunkInfo 附件类型，简化渲染数据管理
2. **同步优化**: 实现完整的区块附件向所有玩家同步机制
3. **UV偏移增强**: 添加纹理UV偏移的客户端-服务端双向同步功能
4. **版本升级**: Laplace API 从 0.5.1 升级至 0.7.1

## ✨ 新特性

### 1. 玩家加入时的绘制渲染初始化（v2.11.1）

#### 客户端侧检查与区块扫描
**文件**: `PainterClient.java` / `PaintClientEvent.java`

- **新增功能**:
  - 添加客户端侧检查确保只在客户端执行渲染逻辑
  - 实现玩家周围区块扫描机制
  - 自动将包含绘制数据的区块添加到渲染缓存
  - 防止渲染残留并提升绘制数据加载效率
  - 修复 Minecraft 实例为空时的异常处理

- **实现细节**:
  ```java
  // 玩家加入时触发
  if (level.isClientSide) {
      // 扫描玩家周围区块
      // 查找包含 PaintInfo 附件的区块
      // 将有效区块添加到 PaintRender.cachedChunks
  }
  ```

- **优势**:
  - 新玩家加入服务器时自动加载附近的绘制数据
  - 避免手动刷新或重新登录才能看到绘制的情况
  - 提升了多人游戏的用户体验

### 2. 区块同步功能（v2.11.3 & v2.11.4）

#### 全玩家同步机制
**文件**: `PaintSyncHelper.java`

- **新增方法**: `syncChunkToAll(Level, BlockPos)`
  - 实现向所有玩家同步区块附件数据
  - 使用 `NetworkSync.syncChunkAttachmentToAll` 进行全玩家同步
  - 集成 `ModAttachments.PAINT_INFO` 附件类型支持

- **优化改进**:
  - 修改调用方式，从单个玩家同步改为向所有玩家同步
  - 移除 player 参数，改用 level 参数实现更广泛的区块同步
  - 提高了网络同步的效率和覆盖范围

- **应用场景**:
  - 玩家放置/移除绘制时立即同步给所有在线玩家
  - UV偏移变更时广播给所有相关玩家
  - 确保多人游戏中绘制数据的一致性

### 3. 纹理UV偏移的客户端同步功能（v2.11.5）

- **新增方法**:

      // 计算新的UV坐标

#### PaintInfo 同步逻辑重构
**文件**: `PaintInfo.java`

- **变更**:
  - 使用 `PaintSyncHelper` 替代 `NetworkSync` 进行同步
  - 实现 `removeRender` 方法中的客户端与服务端同步逻辑
  - 简化 `removeRender` 方法参数，移除不必要的玩家参数

#### PaintOperationHelper 更新
**文件**: `PaintOperationHelper.java`

- **变更**:
  - 修改 `cycleTextureUV` 实现，通过区块附件进行操作
  - 不再直接操作 Paint 对象，而是通过 PaintInfo 间接管理
  - 确保所有UV变更都经过同步机制

#### PaintUtil 纹理旋转优化
**文件**: `PaintUtil.java`

- **变更**:
  - 更新纹理旋转的调用方式，传入方块位置参数
  - 确保旋转操作能够正确定位到对应的绘制数据

## 🔧 功能改进

### 1. PaintChunkInfo 附件系统解耦合（v2.11.0 核心变更）

#### 架构重构
**旧架构**:
```
Level → PaintChunkInfo (IAttachment)
       ↓
   PaintInfo (渲染数据)
       ↓
   PaintRender (渲染缓存)
```

**新架构**:
```
Level → PaintInfo (直接作为附件)
       ↓
   PaintRender (渲染缓存)
```

#### 关键改动

##### 删除 PaintChunkInfo 类
- **移除内容**:
  - `PaintChunkInfo.java` 完整删除
  - 相关的附件注册代码
  - `isChanged` 标记和 `tick` 方法
  - 自定义的同步机制

- **原因**:
  - PaintChunkInfo 作为中间层增加了复杂度
  - 直接使用 PaintInfo 作为附件更简洁
  - 减少了不必要的数据拷贝和同步开销

##### 客户端事件处理清理
- **移除文件**:
  - `PaintClientEvent.java` - 客户端事件处理器
  - `PainterClient.java` - 客户端初始化类

- **替代方案**:
  - 直接在主事件处理器中处理客户端逻辑
  - 使用 `level.isClientSide` 进行环境判断
  - 简化了代码结构

##### PaintInfo 数据管理优化
- **变更**:
  - 直接操作渲染缓存替代原有的 PaintChunkInfo 依赖
  - 更新玩家加入事件和区块加载事件处理
  - 优化渲染缓存管理，简化区块绘制数据的添加和移除逻辑

- **实现**:
  ```java
  // 旧代码
  PaintChunkInfo chunkInfo = chunk.getData(ModAttachments.PAINT_CHUNK_INFO);
  chunkInfo.getRenderNearby(player);
  
  // 新代码
  PaintInfo paintInfo = chunk.getData(ModAttachments.PAINT_INFO);
  paintInfo.render(poseStack, vertexConsumer, frustum);
  ```

##### 反序列化逻辑增强
- **新增**:
  - 在反序列化时清空现有渲染数据
  - 重新加载区块渲染信息
  - 优化区块加载逻辑确保渲染数据正确初始化

- **优势**:
  - 避免了数据不一致问题
  - 确保了存档加载后的渲染正确性

### 2. 绘制信息同步和渲染缓存管理修复（v2.11.2）

#### 客户端侧逻辑优化
- **移除**: 客户端侧的冗余绘制信息删除逻辑，避免重复操作
- **原因**: 服务端已经处理了删除操作，客户端无需重复执行

#### 网络注册方法更新
- **变更**: 更新为块位置集处理器，优化 AO 刷新包处理
- **优势**: 更高效地处理批量位置更新

#### PaintInfo 渲染缓存重构
- **变更**:
  - 统一客户端和服务端处理逻辑
  - 简化 `removeRender` 方法参数
  - 优化绘制放置时的渲染缓存添加

- **实现**:
  ```java
  public void removeRender(BlockPos pos) {
      // 移除渲染对象
      // 同步到所有玩家（如果是在服务端）
      // 标记区块变更
  }
  ```

#### Minecraft 实例检查
- **新增**: 在绘制放置时增加 Minecraft 实例检查
- **原因**: 防止在某些环境下出现空指针异常

### 3. 画作同步一致性修复（v2.11.6）

#### 移除客户端侧条件判断
**文件**: `PaintInfo.java` / `PaintOperationHelper.java`

- **变更**:
  ```java
  // 旧代码
  if (level.isClientSide) {
      // 只在客户端执行
  }
  
  // 新代码
  // 无论在客户端还是服务端都会执行
  ```

- **原因**:
  - 确保画作在不同环境下的同步一致性
  - 避免了某些情况下画作无法正确移除的问题
  - 服务端也需要执行移除逻辑以触发同步

- **影响**:
  - 修复了多人游戏中画作移除不同步的问题
  - 确保了单机和多人模式的行为一致

## 🐛 Bug 修复

### 1. 多人游戏同步问题
- **问题**: 玩家A放置/修改绘制后，玩家B看不到变化
- **原因**: 
  - PaintChunkInfo 的同步机制不够完善
  - 缺少向所有玩家的广播机制
- **修复**: 
  - 实现了 `syncChunkToAll` 全玩家同步
  - 移除了中间的 PaintChunkInfo 层
  - 直接使用 PaintInfo 作为附件进行同步

### 2. 新玩家加入时渲染缺失
- **问题**: 新玩家加入服务器后，需要重新加载区块才能看到已有的绘制
- **原因**: 没有在玩家加入时初始化渲染缓存
- **修复**: 
  - 实现玩家加入时的区块扫描机制
  - 自动将包含绘制数据的区块添加到渲染缓存

### 3. UV偏移同步不完整
- **问题**: UV偏移变更后其他玩家看不到变化
- **原因**: 缺少完整的UV偏移同步链路
- **修复**: 
  - 添加 `getUvOffsets()` 方法
  - 实现 `cycleTextureUV` 和 `setUVOffset` 的同步逻辑
  - 通过 `PaintSyncHelper` 确保双向同步

### 4. 画作移除不同步
- **问题**: 在某些环境下画作移除操作不会同步到其他玩家
- **原因**: 客户端侧的条件判断阻止了服务端的执行
- **修复**: 移除 `level.isClientSide` 条件判断，确保所有环境都执行移除逻辑

## 📝 代码规范

### 1. 网络同步最佳实践
- ✅ 客户端负责发起请求和显示
- ✅ 服务端负责验证和广播
- ✅ 使用 `PaintSyncHelper` 封装同步逻辑
- ✅ 正确标记区块保存状态

### 2. 分布式环境隔离
- ✅ 使用 `level.isClientSide` 进行运行时检查
- ✅ 客户端和服务端职责清晰分离
- ✅ 避免在服务端执行纯客户端逻辑

### 3. Java 注释规范
- ✅ 所有代码注释使用块注释格式
- ✅ 禁止使用行尾注释
- ✅ 注释语言：中文（业务逻辑）、英文（技术术语）

### 4. 架构设计原则
- ✅ 单一职责：每个类只负责一个功能域
- ✅ 解耦合：减少不必要的中间层
- ✅ 简洁性：优先选择简单的实现方案

## 📌 升级注意事项

1. **备份存档**: 建议在升级前备份世界存档
2. **前置依赖**: 确保已安装 Laplace API 0.7.1（重要版本升级）
3. **配置文件**: 无需重置配置文件，向后兼容
4. **网络同步**: 服务器和客户端需同时升级到 v2.11.x
5. **API 变更**: 
   - `PaintChunkInfo` 类已完全移除
   - 直接使用 `PaintInfo` 作为区块附件
   - `PaintSyncHelper.syncChunkToAll()` 取代了旧的单玩家同步方法
   - `AbstractPaint` 新增了 `getUvOffsets()`、`cycleTextureUV()`、`setUVOffset()` 方法

6. **多人游戏**: 
   - 所有玩家必须升级到相同版本以确保同步正常
   - 服务端必须安装 v2.11.x 才能正确处理新的同步机制
   - 新玩家加入时将自动加载附近的绘制数据

7. **迁移指南**:
   ```java
   // 旧代码（已废弃）
   PaintChunkInfo chunkInfo = chunk.getData(ModAttachments.PAINT_CHUNK_INFO);
   chunkInfo.tick();
   chunkInfo.done();
   
   // 新代码
   PaintInfo paintInfo = chunk.getData(ModAttachments.PAINT_INFO);
   // 无需手动 tick 或 done，父类自动处理
   ```
