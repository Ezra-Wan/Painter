## 🎯 版本概览

v2.9.0 是一个专注于**渲染性能优化**和**代码质量提升**的重要更新。本次更新重构了渲染管线的核心逻辑，移除了冗余的距离剔除机制，优化了数据结构，并修复了多个已知问题。

---

## ✨ 新特性

### 1. 渲染管线优化

#### 移除 `shouldRenderFace` 中的远距剔除
- **变更说明**: 从 `RenderUtil.shouldRenderFace()` 方法中移除了基于相机距离的远距剔除逻辑
- **原因**: 
  - 远距剔除已在 `PaintChunkInfo.getRenderNearby()` 中通过视距过滤实现
  - 渲染阶段已有视锥体剔除（Frustum Culling）
  - 避免重复计算，职责更加清晰
- **影响**: 
  - 减少了每次可见性检查的计算开销
  - 代码更简洁，符合单一职责原则
  - 性能无明显下降，因为远距过滤在更早的阶段完成

#### 清理未使用的导入
- 移除了 `Vector3f`、`Object2ByteLinkedOpenHashMap`、`BakedQuad`、`BakedModel` 等未使用的导入
- 提升了代码可读性和维护性

## 🔧 功能改进

### 1. 区块渲染管理

#### 新增 `removeChunkPaint` 方法
- **位置**: `PaintRender.java`
- **功能**: 移除指定区块的所有绘制数据
- **实现细节**:
  ```java
  public static void removeChunkPaint(ChunkPos chunkPos) {
      // 1. 从 levelChunk 获取 PaintInfo
      // 2. 获取 PaintInfo 中的 renders
      // 3. 将所有包含的 renders 从当前缓存 renders 中移除
      // 4. 标记渲染数据已更改，触发重绘
  }
  ```
- **应用场景**: 
  - 区块卸载时清理渲染缓存
  - 玩家远离某区域后的资源释放
  - 防止内存泄漏

### 2. 数据结构优化建议

#### NBT 序列化优化分析
- **visibles 缓存评估**:
  - 数据量: 最多 12 个布尔值（6方向 × 正负标志）
  - NBT 大小: ~240 bytes/Paint
  - 增长比例: +22%（相对于当前 ~1000 bytes）
  - **结论**: 暂不持久化，采用运行时 TTL 缓存策略更优

- **aoFaces 缓存评估**:
  - 数据量: 最多 6 个 AO Face 对象
  - NBT 大小: ~900 bytes/Paint
  - 增长比例: +90%
  - **结论**: 不建议持久化，使用对象池 + 短期缓存

## 🐛 Bug 修复

### 1. 区块异步加载导致的渲染状态不同步
- **问题描述**: 区块从磁盘加载时，`deserializeNBT` 中立即执行可见性刷新可能基于错误的方块状态
- **解决方案**: 使用 `Minecraft.getInstance().execute()` 延迟到下一帧执行，确保区块完全加载
- **影响范围**: `AbstractPaint.deserializeNBT()`

### 2. 视距计算不一致问题
- **问题**: `RenderUtil.shouldRenderFace` 中的距离计算与 `PaintChunkInfo.getRenderNearby` 不一致
- **修复**: 统一在 `getRenderNearby` 中进行视距过滤，移除 `shouldRenderFace` 中的重复逻辑
- **规范遵循**: 符合"距离阈值一致性规范"

### 2. 距离计算优化

#### 平方距离替代欧氏距离
- **现状**: `RenderUtil` 中已移除距离计算
- **建议**: `PaintChunkInfo.getRenderNearby` 应使用平方距离比较
- **代码示例**:
  ```java
  int viewDistance = mc.options.getEffectiveRenderDistance() + 6; // +6 视距补正
  int viewDistanceSquared = viewDistance * viewDistance;
  
  if (playerPos.distanceSquared(chunkPos) <= viewDistanceSquared) {
      // 在视距内
  }
  ```
- **收益**: 避免开方运算，提升性能
- **规范遵循**: 符合"距离计算使用平方距离优化"和"远距渲染视距补正规范"

### 3. 增量更新机制（待实施）

#### 当前问题
- `redraw()` 每次都会全量重建 `renders` 缓存
- 即使只有少量变化，也会重新获取所有数据

#### 优化方案
```java
public static void redraw() {
    // 增量更新：只移除不在新集合中的，添加新出现的
    renders.keySet().removeIf(pos -> !newRenders.containsKey(pos));
    newRenders.forEach((pos, render) -> {
        renders.putIfAbsent(pos, render);
        render.update();
    });
}
```
- **预期收益**: 减少对象创建和 GC 压力
- **优先级**: P1（中）
