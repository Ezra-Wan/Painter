## 🎯 版本概览

v2.10.x 是一个专注于**网络同步功能增强**和**UV偏移管理**的重要更新。本次更新主要完成了以下工作：

1. **UV偏移同步系统**: 实现了完整的客户端-服务端UV偏移数据同步机制
2. **网络架构扩展**: 新增服务器端网络处理器，支持双向数据同步
3. **代码优化**: 简化了纹理UV循环逻辑，移除了特殊处理分支
4. **版本升级**: 从 v2.9.6 升级至 v2.10.1

## ✨ 新特性

### 1. UV偏移同步功能（v2.10.0 核心变更）

#### 服务器端网络处理器
**新增文件**: `ServerHandlers.java`

- **功能**: 注册并处理来自客户端的网络请求
- **实现**:
  ```java
  public class ServerHandlers {
      public static final ResourceLocation CYCLE_TEXTURE_UV_PACKET = 
          ResourceLocation.fromNamespaceAndPath(Painter.MODID, "cycle_texture_uv");
      
      public static void register() {
          NetworkRegister.registerClientRequestHandler(
              CYCLE_TEXTURE_UV_PACKET, 
              ((packet, context) -> cycleTextureUVHandler(packet, context))
          );
      }
  }
  ```

- **数据包处理流程**:
  1. 接收客户端发送的UV偏移数据包
  2. 解析 BlockPos、Direction、UV坐标
  3. 在服务端设置UV偏移值
  4. 标记区块为未保存状态（`chunk.setUnsaved(true)`）
  5. 同步到所有加载该区块的玩家

#### PaintSyncHelper 增强
**文件**: `PaintSyncHelper.java`

- **新增方法**: `syncPaintUV(BlockPos, Direction, float[])`
  - 将UV偏移数据打包为 CompoundTag
  - 通过 `NetworkSync.requireToServer()` 发送到服务端
  - 使用新的 `CYCLE_TEXTURE_UV_PACKET` 数据包类型

- **实现细节**:
  ```java
  public static void syncPaintUV(BlockPos blockPos, Direction direction, float[] uv) {
      CompoundTag tag = new CompoundTag();
      tag.putInt("x", blockPos.getX());
      tag.putInt("y", blockPos.getY());
      tag.putInt("z", blockPos.getZ());
      tag.putString("direction", direction.getName());
      tag.putFloat("u", uv[0]);
      tag.putFloat("v", uv[1]);
      
      NetworkSync.requireToServer(ServerHandlers.CYCLE_TEXTURE_UV_PACKET, tag);
  }
  ```

### 2. AbstractPaint UV循环优化

**文件**: `AbstractPaint.java`

#### 客户端限制注解
- 在 `cycleTextureUV()` 方法上添加 `@OnlyIn(Dist.CLIENT)` 注解
- 明确标识此方法仅在客户端调用
- 防止服务端误调用导致的逻辑错误

#### UV同步集成
- 在 `cycleTextureUV()` 方法末尾自动调用 `PaintSyncHelper.syncPaintUV()`
- 确保每次UV变更后立即同步到服务端
- 移除了注释掉的旧代码 `uvOffsets.put(flag, new float[]{newU, newV})`

#### 文档完善
- 添加了中文注释说明方法的客户端限定性质
- 明确了数据同步的工作流程

## 🔧 功能改进

### 1. PaintOperationHelper 简化

**文件**: `PaintOperationHelper.java`

#### 移除 SlabBlockPaint 特殊处理
- **旧代码**:
  ```java
  public static void cycleTextureUV(AbstractPaint paint, Direction direction) {
      if(paint instanceof SlabBlockPaint slabBlock) {
          slabBlock.cycleTextureUV(direction);
      }
      else paint.cycleTextureUV(direction);
  }
  ```

- **新代码**:
  ```java
  @OnlyIn(Dist.CLIENT)
  public static void cycleTextureUV(AbstractPaint paint, Direction direction) {
      paint.cycleTextureUV(direction);
  }
  ```

- **改进点**:
  - 消除了不必要的类型检查分支
  - 统一了所有 Paint 类型的处理逻辑
  - 添加了客户端限定注解，防止服务端调用
  - 代码更简洁，性能略有提升

#### 导入清理
- 移除了未使用的导入
- 新增了必要的导入：
  - `net.neoforged.api.distmarker.Dist`
  - `net.neoforged.api.distmarker.OnlyIn`
  - `net.neoforged.neoforge.network.PacketDistributor`

### 2. PaintUtil 逻辑优化

**文件**: `PaintUtil.java`

#### 客户端验证增强
- **变更**: 在调用 `cycleTextureUV()` 前增加客户端检查
  ```java
  // 旧代码
  PaintOperationHelper.cycleTextureUV(paint, direction);
  
  // 新代码
  if(level.isClientSide) PaintOperationHelper.cycleTextureUV(paint, direction);
  ```

- **原因**: 
  - 确保UV循环操作只在客户端执行
  - 避免服务端重复执行导致的数据不一致
  - 符合"客户端计算，服务端验证"的网络同步模式

#### PaintInfo 访问优化
- **变更**: 直接使用附件系统获取 PaintInfo
  ```java
  // 旧代码
  Map<BlockPos, AbstractPaint> paints = PaintAttachmentHelper.getPaintInfo(chunk).getPaints();
  
  // 新代码
  PaintInfo paintInfo = chunk.getData(ModAttachments.PAINT_INFO);
  Map<BlockPos, AbstractPaint> paints = paintInfo.getPaints();
  ```

- **优势**:
  - 减少了辅助方法调用层级
  - 代码更直观易懂
  - 性能略有提升

### 3. Painter 主类初始化

**文件**: `Painter.java`

#### 服务器端处理器注册
- **新增**: 在主类初始化时注册 `ServerHandlers`
  ```java
  // 注册网络处理器
  if(FMLEnvironment.dist == Dist.CLIENT) ClientHandlers.register();
  ServerHandlers.register();  // 新增
  ```

- **说明**: 
  - 客户端处理器仍然只在客户端环境注册
  - 服务器端处理器在所有环境注册（包括单机整合环境）
  - 确保了网络同步功能的完整性

## 🐛 Bug 修复

### 1. UV偏移数据丢失问题
- **问题**: 在多人游戏中，玩家A修改UV偏移后，玩家B看不到变化
- **原因**: UV偏移数据仅在客户端本地存储，未同步到服务端
- **修复**: 
  - 实现了完整的双向同步机制
  - 客户端修改后立即发送到服务端
  - 服务端验证后广播给所有相关玩家
  - 区块数据正确标记为需要保存

### 2. 服务端异常调用问题
- **问题**: `cycleTextureUV()` 可能在服务端被意外调用
- **修复**: 
  - 添加 `@OnlyIn(Dist.CLIENT)` 注解
  - 在调用处增加 `level.isClientSide` 检查
  - 双重保护确保逻辑只在客户端执行

## 📌 升级注意事项

1. **备份存档**: 建议在升级前备份世界存档
2. **前置依赖**: 确保已安装 Laplace API 0.5.1
3. **配置文件**: 无需重置配置文件，向后兼容
4. **网络同步**: 服务器和客户端需同时升级到 v2.10.x
5. **API 变更**: 
   - `PaintOperationHelper.cycleTextureUV()` 现在只能在客户端调用
   - UV偏移数据会自动同步到服务端，无需手动处理
   - 移除了 SlabBlockPaint 的特殊处理逻辑

6. **多人游戏**: 
   - 所有玩家必须升级到相同版本以确保同步正常
   - 服务端必须安装 v2.10.x 才能正确处理UV同步请求
